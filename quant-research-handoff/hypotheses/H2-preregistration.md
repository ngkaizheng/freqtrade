## 0. 背景：H1 确立的 trade-off

H1 检验（`backtest_output/h1_decision.md`）确认了一个**机制性的权衡**：

| 触发条件 | 反应速度 | whipsaw/换手 | 崩盘保护 |
|---|---|---|---|
| `Close<MA200` | 快（滞后 16.1 天） | **高**（换手 2.6-5.3） | **好** |
| `MA50<MA200` | 慢（滞后 62.9 天） | **低**（换手 0.35-0.81，降 75-88%） | 较差（Validation 层回撤恶化最多 +11.19pp） |

H1 判定：**减少 whipsaw 成立，保持回撤保护不成立**。

---

## 1. 假设陈述（冻结，单一版本）

> **H2**：使用**快速信号做第一次减仓**、**慢速确认做第二次减仓**的分层暴露规则，
> 能同时接近 `Close<MA200` 的风险保护水平与 `MA50<MA200` 的低换手水平。

### 机制依据

H1 已测得两个信号的反应速度差约 **4 倍**（16.1 天 vs 62.9 天）。
H2 的设计假设：**快速信号负责及早保护，慢速信号负责确认后才加大减仓** ——
即让「保护」与「摩擦」由不同信号分别承担。

---

## 2. 冻结的规则（H2 唯一版本，无参数）

### 暴露映射（纯状态映射，无路径依赖）

| 条件 | 股票暴露 |
|---|---|
| `Close >= MA200` | **100%** |
| `Close < MA200` 且 `MA50 >= MA200` | **75%** |
| `Close < MA200` 且 `MA50 < MA200` | **50%** |

### 关于恢复条件的说明（重要，冻结前已明确）

用户指定的恢复路径为「`MA50>=MA200` → 75%，然后 `Close>=MA200` → 100%」。
该路径与上表**完全等价** —— 上表是一个**纯函数映射**，`暴露 = f(Close, MA200, MA50)`，
**不含滞后项、不含状态记忆、无路径依赖**。

因此恢复行为自动由映射决定，无需单独的恢复规则：
- 从 50% 恢复：`MA50` 先回到 MA200 上方 → 75%；`Close` 再回到 MA200 上方 → 100%
- 从 75% 恶化：`MA50` 跌破 MA200 → 50%
- 从 75% 恢复：`Close` 回到 MA200 上方 → 100%（跳过中间态）

**这消除了「跑完再决定恢复条件」的可能。**

### 冻结参数

| 项目 | 值 | 说明 |
|---|---|---|
| 慢线 | **MA200** | 固定，不做 150/180/220/250 挖掘 |
| 快线 | **MA50** | 固定，不做 20/30/40/60 挖掘 |
| 分层 | **100 / 75 / 50** | **单一版本，不做 70/40、80/50 等变体** |
| 成交 | 信号当日收盘产生，**次日开盘**成交 | |
| 成本 | **10 / 20 / 50 bps** | 正式条件 |
| 资产 | **SPY / QQQ / IWM / EEM** | 固定，不重新挑资产 |
| 参数优化 | **无**。任何调整使本预注册作废 | |

### 四条对比臂（冻结）

| 臂 | 定义 |
|---|---|
| **A: BH** | 一直持有 100% |
| **B: Close→50%** | `Close<MA200` → 50%，否则 100% |
| **C: MA50→50%** | `MA50<MA200` → 50%，否则 100% |
| **D: H2 分层** | 见上表（100/75/50） |

**B 与 C 的存在是为了区分：H2 的改善究竟来自「分层设计」，还是仅仅因为它介于 B 和 C 之间。**

## 4. 终点定义（冻结）

### 主要终点 1：风险（Risk endpoint）

| 指标 | 定义 |
|---|---|
| 最大回撤 | 全期 |
| **最差下跌区间表现** | 四个重大崩盘 episode 中的回撤（见 §5） |
| 恢复天数 | 回撤谷底回到前高 |

### 主要终点 2：摩擦（Friction endpoint）

| 指标 | 定义 |
|---|---|
| 换手 | 年化双边 `Σ\|Δw\| / 年数` |
| **暴露变化次数** | 权重发生变化的次数（100→75、75→50、50→75、75→100 各计 1 次） |
| 成本调整后 CAGR | 10/20/50bps 三档 |

> ⚠️ **必须统计「暴露变化次数」而非仅「完整买卖次数」** ——
> H2 可能产生 `100→75→100→75→50→75→100` 的来回调整，
> 只数完整进出会低估实际操作负担。

### 次要终点

`Sharpe` / `Sortino` / `CAGR`

### 判定规则（冻结，先于结果）

**机制假设成立（H2 达成设计目标）**：4 个资产中**至少 3 个**在 Validation 层同时满足
1. **风险端**：最大回撤**不差于**臂 B 超过 **3pp**（即 `|DD_D| - |DD_B| <= 3pp`）
2. **摩擦端**：换手**低于**臂 B 至少 **30%**（即 `(turn_B - turn_D)/turn_B >= 30%`）

**超出 B/C 的中庸解释（必须排除）**：若 H2 的所有指标都恰好落在 B 与 C 之间
（既不明显优于 B 的风险端，也不明显优于 C 的摩擦端），则 H2 **未提供分层设计的增量价值**，
判定为「无增量价值」而非「支持」。

**结论分档：**
- **支持 H2**：Research 与 Validation 两层**均**达成上述机制假设
- **部分支持**：仅 Validation 层达成
- **无增量价值**：H2 指标全部落在 B 与 C 之间
- **不支持**：机制假设未达成

**Holdout 只用于报告，不用于修改规则、阈值或分层比例。**

## 5. 崩盘 episode 分解（冻结）

对四个 episode，测量每条臂的**首次减仓时点与幅度**：

| Episode | 峰值 | 谷底 |
|---|---|---|
| 2000-2002 互联网泡沫 | 2000-03-24 | 2002-10-09 |
| 2007-2009 金融危机 | 2007-10-09 | 2009-03-09 |
| 2020 新冠 | 2020-02-19 | 2020-03-23 |
| 2022 加息熊市 | 2022-01-03 | 2022-10-12 |

每条臂记录：**峰值后第几个交易日首次减仓**、**谷底时的暴露水平**、**该 episode 内承受的回撤**。

**关键问题**：H2 是否在快速崩盘中获得臂 B 的保护速度，同时避免臂 C 的迟滞？

---

## 6. 什么会证伪 H2

1. H2 的换手**没有**明显低于臂 B（<30% 降幅）→ 快信号主导，分层无意义
2. H2 的最大回撤**明显差于**臂 B（>3pp）→ 慢信号拖累了保护
3. H2 的所有指标都落在 B 与 C 之间 → 分层设计无增量价值
4. 四个 episode 中 H2 的首次减仓时点**全部**晚于臂 B → 快信号未生效
5. 方向在 Research 与 Validation 两层不一致 → 不稳定

---

## 7. 统计表述纪律（沿用 H1）

- **最大回撤**：不使用「统计显著」，改用「在 N/M 个资产/窗口中一致」
- **Sharpe**：报告 95% 置信区间（Lo 2002 月度口径）
- **换手/变化次数**：报告绝对值与相对变化
- **H2 失败即记录失败**，不回头调分层比例；后续问题以 H3 重新预注册
