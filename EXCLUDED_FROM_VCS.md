# What is deliberately NOT in version control, and why

**Written:** 2026-09-30, at the first commit of the research corpus.
**Nothing on this list has been deleted.** Every file listed here is still on disk at the
path shown. This document exists so that "not committed" is a **decision with a reason**
rather than a **silent omission** — which is how the two deployed strategies nearly went
uncommitted in the first place, and how `docs-myself/` became unrecoverable through git
after the workspace was lost twice.

---

## 1. The two categories, and they are not the same thing

| category | what it is | in the repo? | recoverable if the disk dies? |
|---|---|---|---|
| **A. Deliberate exclusions** | the 26 files in §2 | no, **by decision** | **NO — and this is the risk** |
| **B. Correctly excluded** | configs, sqlite, market data, `.venv` | no, by upstream rule | **yes — all re-creatable** |

**Category B is fine.** `config*.json` is regenerated by hand (and documented field by field
in `docs-myself/DELIVERABLE_SPEC_2026-09-30.md` §3); `*.sqlite` is a runtime database;
`user_data/data/**` re-downloads from Binance Vision; `.venv` reinstalls from
`requirements.txt`. Nothing is lost by their absence from git.

**Category A is the real exposure**, because none of it can be re-downloaded. If the disk
fails, those 26 files are gone. See §4 for the options.

**Security checks run before that commit:** 0 API-key-shaped strings, 0 `*.sqlite`,
0 `*.feather` / `*.parquet` / `*.zip`, 0 `config*.json`. The two trading configs were
**verified to have empty `key` and `secret`** and were still left out, because a file named
`config_*.json` is the one type where an empty string today becomes a live key tomorrow.

## 4. If you want the 26 kept somewhere durable, in order of preference

1. **A separate PRIVATE repository of your own** (not the fork). One command, nothing in
   the fork changes, and the upstream PR capability is preserved:
   ```powershell
   git init "E:\FreqTrader\research-private"
   # copy the 26 in, then:  git add -A && git commit -m "reference PDFs + personal notes" && git push
   ```
2. **Make the fork private, then commit them.** This works, but it **detaches the repo
   from the fork network** — you lose the ability to open PRs to freqtrade from it, and
   because a repo named `freqtrade` already exists in your account, re-attaching is not
   available. Effectively one-way.
3. **Leave them on disk only.** Simplest, and what the current state is. Accepts the risk
   that a second disk failure loses them.

To include them in the current fork anyway:
```powershell
git add -f docs-myself/Note-From-Wechat.pdf tools/carry/*.pdf protocols.json
git commit -m "add third-party reference PDFs" && git push origin research
```
