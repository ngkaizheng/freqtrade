# 巧合度仓位加权：REJECTED（关键门 C-4 失败）

**预注册：** `PREREG_SIZING_COINCIDENCE_2026-09-29.md`
**结果：本文件。这是本项目第一个「机制成立但修法不管用」的设计。**

---

## 0. 一句话

**机制是真的（13+ 同时触发时市场跌 4.678%，是其他档的 3 倍），
但把它变成仓位规则之后，最大回撤不降反升 33.6%，
最严格的依赖处理还变差了。按预注册的关键门，REJECTED。**

---

## 1. 机制（先于任何 P&L，独立测过）

`market_check.py`，515 币，每个出现信号的 bar 上等权面板的前瞻 42 根收益：

| 同时触发数 | bar 数 | 前瞻市场收益 | t |
|---|---:|---:|---:|
| 1 | 409 | −1.465% | −3.26 |
| 2 | 121 | −1.928% | −2.27 |
| 3–4 | 93 | −1.950% | −1.99 |
| 5–7 | 62 | −2.645% | −2.14 |
| 8–12 | 41 | −1.583% | −1.20 |
| **13+** | **117** | **−4.678%** | **−4.61** |

**13+ 那一档的市场跌幅是其他档的约 3 倍，而且只有它的 t 过了 −4。**
这是可实盘观测的（数一下这根 bar 上有多少个币发了信号），不是只能回测算的东西。

---

## 2. 设计

```
if 同一根 bar 上同时触发的币数 >= 13:   size = 1.0 x base
else:                                    size = 0.5 x base
```

`Q = 13` 是巧合度分布的 **85 分位**，在跑之前定死，不是搜出来的。
信号、4.0×ATR 止损、2R 目标、42 根时间止损、宇宙、流动性档、成本、熔断**全部冻结**。
**只动仓位大小。**

## 4. ⚠ 而且「总风险匹配」这个前提本身是错的

预注册要求总风险保持不变，做法是把基础风险除以平均仓位乘数 0.5695，
即从 1% 提到 1.756%。

**但 `max_stake_frac = 0.25` 的单仓上限在这个水平上不再紧绑，
于是实际敞口上升了——交易数从 862 涨到 1,253，峰值并发从 17 涨到 24。**

**所以这个对比从一开始就不是「同样的总风险」，而是「更大的总风险」。**
账户数字看起来更好（+140% vs +90%）正是这个原因，
**而回撤变差也是这个原因。**

> **这是一次设计失败，不是一次发现。** 一个「让总风险匹配」的实现，
> 如果不检查那个限制它匹配的东西有没有变紧，就只是一个更大的仓位。
> **风险匹配必须验证，不能断言**——这和「不要相信画出来的图，要数交易数」是同一条。

## 5. 教训

**「机制成立」和「修法有效」是两件事，而且这个项目已经撞上这个模式两次了：**

| 案例 | 机制 | 修法 |
|---|---|---|
| `RegimeBreakoutExitStudy`（5m） | 出口诊断正确 | 6 个臂全空 |
| `PerpShort4hSwitch`（方向切换） | 牛市确实失血 | 加多头腿让 +52% 变 −59% |
| **本次（巧合度加权）** | **13+ 档市场跌幅是 3 倍** | **回撤从 31.5% 涨到 42.1%** |

**三次都是同一个形状：一个被独立测出来的机制，放进一个策略里时，
机制本身被另一个约束吃掉了。**
这次的约束是**仓位上限**——一个看起来只是实现细节的 `max_stake_frac`。

## 6. 判词

**REJECTED。** 按预注册：C-4 是关键门（**「如果回撤没降，这条规则就没有解决它要解决的问题，
就算均值 R 变好也拒绝」**），而 C-4 不仅失败，还反向了。

**交付物不变**：仍然是 `PerpShort4hDeploy`
（实测 COVID 成本 +89.9%、Sharpe 0.67、最大回撤 31.5%、4 年里 3 年为正）。

**如果要压回撤，本项目唯一**已经**测过并且有效**的方式是降风险预算**
（`PERP_DEPLOY_2026-09-28.md` §3 的风险曲线：0.5%/笔把回撤从 47% 砍到 27%），
**而不是重新分配它。**
