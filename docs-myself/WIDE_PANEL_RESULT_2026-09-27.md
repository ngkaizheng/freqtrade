# 宽面板 + freqtrade 交叉验证 — 结果（2026-09-27）

**预注册：** `docs-myself/PREREG_WIDE_PANEL_2026-09-27.md`（运行前冻结）
**跨引擎验证：** 本文第 6 节。**这是本项目第一次由第二个独立引擎复现的结果。**

---

## 0. 结论

**找到了一条真实的、跨引擎可复现的、但仍未达到显著性门槛的边。**
**做多腿在每一个格子、每一种成本下都亏钱。全部收益在空头腿。**

| | 结果 |
|---|---|
| 空头腿，104 个永续，4h，1.5 ATR + 低波动过滤 | **净 +0.1757R/笔**，n = 4,144 |
| t_adjusted | **1.8746**（门槛 2.0，**差 6.7%**） |
| PBO（CSCV） | **0.00** |
| 个体为正的 symbol 占比 | **82.7%** |
| 4 个时间切分 | **4/4 为正** |
| 去掉最好的那个 symbol | **+0.1704R**（仍为正） |
| 34.9 bps 压力成本 | **+0.1119R**（仍为正） |
| 与 BTC 的相关性 | **−0.314**（R² = 0.099） |
| **freqtrade 独立引擎复核** | **1,021 笔 vs shark 1,024 笔，PF 1.36，均为正** |

**这是一个"差一点"，不是通过。** 而且空头腿是在全样本上选出来的，
所以**正确的下一步是前瞻测试，不是继续在样本内挖。**

## 1. 为什么做宽面板：修的是样本量，不是参数

4h 交易原本 `lag-1 AC = −0.004`、IAT = 1.0（`phase3_effective_sample_size.csv`），
看起来每笔都是独立观测。宇宙从 9 个扩到 **104 个**（规则：2023-01-01 前上线且
仍在交易的 USDT 永续，排除 `BTCDOMUSDT` 指数合约），每笔独立时 t 应按 `sqrt(N)` 涨。

> **⚠ 这个推理错了，而且错法值得记下来。**
> 名义交易数 1,690 → 16,838（**9.97×**），但 **IAT 从 1.0 涨到 16.3**，
> 于是 **n_effective 反而从 1,690 掉到 1,031**。
> 104 个 symbol 在同一根 bar 上一起触发（**72% 的交易与别的交易共享时间戳**），
> 1 维 IAT 把"同时发生"读成了"序列相关"。
>
> **教训：n_effective 不等于 n/IAT，除非 IAT 真的度量时间序列依赖。
> 同一时刻的横截面聚集必须先聚类再算依赖。**

## 2. 依赖诊断（`tools/widepanel/dependence.py`）

以 B1.5 / calm 为例，7,914 笔交易只落在 2,222 个不同时间戳上。

| 切法 | n | IAT | t |
|---|---:|---:|---:|
| 逐笔 | 7,914 | 13.21 | 1.39 |
| **逐时间戳均值** | 2,222 | 1.79 | **−1.44** |
| **周度 P&L** | 189 | 1.00 | **1.29** |
| **独占时间戳的交易** | 1,226 | 1.17 | 均值 **−0.0892R** |
| **共享时间戳的交易** | 6,688 | 14.13 | 均值 **+0.1127R** |

> **独占突破（只有它自己在动）是亏的。只有在大量合约同时突破时才有 edge。**
> 这正是 §3.24 那个陷阱的上一层版本。

**β = 1.000，α = 0.0000**（对同一时间戳的横截面均值回归）。
> 每一 R 的波动都是市场共同的成分，个体残差 sd 0.855R vs 原始 1.437R。
> **整个多头+空头组合就是一个纯粹的方向性市场多头赌注，戴着成交量过滤器的外衣。**

## 3. 多空腿分解 —— 本项目最重要的一条

`tools/widepanel/legs.py`，规则在运行**之前**写下：若空头腿承载 edge，
则做空可行；若多头腿承载，则结果是伪装成信号的买入持有，**该线关闭**。

| 成本 | cell | 多头净 R | 多头 t | **空头净 R** | **空头 t** |
|---|---|---:|---:|---:|---:|
| calm 12.0 | A1.0 | −0.0365 | −0.84 | **+0.1102** | 1.41 |
| calm 12.0 | A1.5 | −0.0409 | −0.81 | **+0.1533** | 1.87 |
| calm 12.0 | B1.5 | −0.0222 | −0.32 | **+0.1757** | **1.87** |
| 22.8 | B1.5 | −0.0582 | −0.84 | **+0.1456** | 1.55 |
| **34.9** | **B1.5** | **−0.0986** | **−1.43** | **+0.1119** | 1.19 |

> **12 个格子里，多头腿全部为负。没有任何例外。**
> 这与 §3.27（Liu-Tsyvinski-Wu：收益在空头腿）和 §3.24（单边书可能是伪装成
> 横截面服饰的市场 beta）在**一个全新的 104 名面板上被独立复现。**

**⚠ 但这是"在结果上做选择"。** 丢掉亏损的那条腿，正是制造 Sharpe 的标准手法。
所以空头腿单独立了预注册（`tools/widepanel/shortleg.py` 文件头），
门槛在看到数字**之前**冻结。

## 4. 低波动 regime 过滤器 —— 文献预测成立

冻结定义（Kurth et al. arXiv:2607.01550，⚠ **预印本**）：
`vol42 < vol42 在过去 365 根 bar 的中位数`，全部用决策前的 bar。

| cell | 毛 R（无过滤） | 毛 R（低波动） | 变化 | 保留交易 |
|---|---:|---:|---:|---:|
| 1.0 ATR | 0.0824 | 0.1137 | **+38%** | 51% |
| 1.5 ATR | 0.0843 | 0.1202 | **+43%** | 52% |

> **过滤器把毛 edge 抬高了 38–43%，而 §1c 算出的 f=0.5 打平门槛是 +33%。**
> **它过了门槛。** 这是整份文献核查里唯一一个有实证支持的过滤器，
> 方向也和直觉相反（**低波动赚钱，高波动亏钱**）。

## 6. freqtrade 独立引擎复核 —— **通过了**

`user_data/strategies/WideShortBreakout.py`，同样 24 个 symbol、同样冻结规则、
同样只做空。两个完全独立的引擎：

| | shark engine | **freqtrade backtesting** |
|---|---:|---:|
| 交易数 | 1,024 | **1,021** |
| 止损出局 | 56.9% | 58.8% |
| 到达 2R 目标 | 39.8% | 34.0% |
| 时间止损 | 3.1% | 7.1% |
| 胜率 | 42.1% | 37.8% |
| 结果 | **+0.1985 R/笔** | **+42.06%，PF 1.36，Sharpe 1.93** |

**两个引擎在交易数上一致到 0.3%，在方向和量级上一致。**
这是 `AGENTS.md` §3.4（"两个阶段用同一个 id 测了两个东西，差 21.8×"）
第一次被一个**外部引擎**正面解决。

**已知近似（已声明）：** freqtrade 用**固定** 3.6% 止损（本面板 1.5×ATR%
的中位数，实测 min 1.47% / median 3.61% / max 5.04%），而不是逐 bar 的自适应
ATR 止损。这是目标率 39.8% vs 34.0% 差异的来源。

### 复核过程中抓到的三个 bug（都是"自信地输出错误"，不是报错）

1. **时间止损单位错误。** 用 `total_seconds() / 240`（240 是每秒小时数）当 bar 数，
   于是一根 4h bar 读成 60 根，**1,338 笔里 1,133 笔在第一根 bar 就被强平**。
   产出：−31.72%、PF 0.58 —— **看起来像是对 shark 结果的证伪，其实是纯单位错误。**
2. **止损棘轮。** `custom_stoploss` 用 `ATR / current_rate` 算距离，
   于是**空头越不利、返回的止损越紧**，3 根 bar 内平掉亏损单，
   而盈利单永远到不了 2R。产出：−22.44%、PF 0.67。
   改成锚定入场价后 `custom_stoploss` 大部分调用返回 `None`，
   于是 −50% 默认止损生效，**只有 0.5% 的交易被止损**（shark 是 57%）。
3. **数据布局三连错。** freqtrade 的 `datadir` **只认命令行参数**
   （`configuration.py:212` 无条件覆盖 config 里的同名字段）；
   文件名是 `{pair}-{timeframe}-{candletype}`（pair 在前，不是 timeframe 在前）；
   永续 candle 必须保留 tz-aware UTC。

> **这三条都属于 `RESEARCH_STATE` §3.32 那一族：一个比较静默地变成了另一个东西。**

## 7. 冻结门槛裁决（`tools/widepanel/shortleg.py`）

| 门槛 | 结果 | 裁决 |
|---|---|---|
| S1 t_adjusted ≥ 2.0 | **1.8746** | **FAIL**（差 6.7%） |
| S2 PBO < 20% | 0.0000 | PASS |
| S3 ≥50% symbol 为正 | 82.7% | PASS |
| S4 ≥3/4 切分为正 | 4 | PASS |
| S5 去掉最好 symbol 仍为正 | +0.1704R | PASS |
| S6 34.9 bps 下仍为正 | +0.1119R | PASS |
| S7 \|与 BTC 相关\| < 0.5 | −0.314 | PASS |

**6/7 通过。唯一不过的是显著性，差 6.7%。**

> **S7 的门槛一开始是我写错的**：用 `|beta| < 0.5` 判断"是不是市场赌注"。
> 但 R 单位下的 beta 是**尺度相关**的 —— BTC 7 日方差很小，
> −0.314 的相关性会打印成 beta = −6.34，于是毫无理由地失败。
> 改成尺度无关的相关系数后 R² = 0.099，**只有 10% 的方差是市场方向**。
> 这是修正一个**规格错误的门槛**，且在读到数值之前完成。

## 8. 它现在是什么，不是什么

**是：**
- 一条 4h 的、永续合约的、**只做空**的规则，104 个标的，3.65 年，
  4,144 笔，净 **+0.176R/笔**，82.7% 的标的为正，4/4 切分为正，
  扛得住 2.9 倍的成本，**并且被一个独立引擎复现**。
- 一次**真实但不显著**的发现。

**不是：**
- **不是通过。** t = 1.87 < 2.0。
- **不是 alpha。** 多头腿全负，β=1.000 —— 它更像"市场方向的择时"，
  而 §3.24/§3.27 都说过这种形状常常只是 beta 的服饰。
- **不是已确认的。** **空头腿是在全样本上选出来的**，
  所以上面的切分数字是**诊断**，不是**确认**。

**下一步只有一个有意义的动作：把这条规则冻结，前瞻跑。**
需要多少时间：n_effective ≈ 239 对应 t=1.87；
要 t=2.0 需要 snr 从 0.1213 涨到 0.1294。
在同样参数下大约需要 **1.1 倍的样本 ≈ 4 年**（104 个标的）。
**除非成本下降或标的数上升，否则这个设计在可预见的未来无法自证。**
这一点必须现在就说清楚，而不是等跑完一年再发现。

## 9. 本轮新增的坑

- **`n_effective` 不能用 n/IAT 除非 IAT 度量的是时间依赖。**
  同一时刻的横截面聚集会把 IAT 从 1 抬到 16，让"扩宇宙"净效果为负。
- **两个引擎的 stoploss 语义不同，不能想当然地移植。**
  shark 固定入场 ATR；freqtrade 的 `custom_stoploss` 是相对当前价且只许收紧。
- **freqtrade 的 `datadir` 只认 `--datadir` 命令行参数**，config 里的会被覆盖。
- **pandas `resample("M")` 在本环境已失效**（须用 `"ME"`）。
- **`Path("X.csv.gz").stem` 是 `"X.csv"`，不是 `"X"`** ——
  这一个字符让"104 个 klines + 104 个 funding"报告成 "0 可用，0 丢弃"，
  每个文件都在磁盘上，整条流水线看起来很健康。
