## 2. 熔断是什么，为什么是它

面板那个结果指明了伤害的真正来源：**72% 的交易与别的交易共享时间戳，
横截面均值的 beta = 1.000。** 这个账是**同时**在很多标的上开的，而它们不独立。
4h 实测的**并发峰值是 18 个仓位同时持有**，中位数 7。

引擎「止损精确在止损价成交」，所以**回测根本产生不出级联的代价**。
我算的压力数字是：**1% 风险下，18 个仓位全部跳空 50% 越过止损，一个瞬间损失约 27% 的账户。**

熔断不能阻止那一个瞬间，但它能阻止**第二、第三个、第四个**——
这就是「一个糟糕的季度」和「账户归零」的区别。

### ⚠ 熔断是在样本内调的

`breaker_max_dd = 0.20` 是**看着 2023–2026 的回撤挑的**，
然后在**同一段数据**上被评判。

**这正是你授权的那个妥协，也是研究仓库会禁止的那件事。** 写在这里，
是为了不让任何后来的人把它误当成一个经过验证的风控。
**它真正的样本外版本是一次前瞻测试，而本项目提供不了。**

> **而且它看起来「有效」这件事本身就要警惕：**
> 熔断把这个回测的回测收益从 +57.9% 抬到了 +78.61%（**+36%**）。
> **一个诚实的风控不应该让样本内收益变好这么多。**
> 这几乎肯定是它切掉了对的那几段，也就是过拟合的表现，不是优点。

## 2.5 实测结果（熔断修好之后）

**⚠ 先说一个测量问题，它影响你读哪一列。**
freqtrade 自己报告的最大回撤是 **`free + used`**，而 `used` 按**入场时的保证金**记账，
**不按市价盯市**。所以**引擎报告的回撤偏乐观**。
本项目的重放（`cost_frontier.py`）按真实净值路径算，数字更大。
**两个都列出来，不要只信引擎那个。**

| | 引擎原始输出 | 成本重放（真实净值路径） |
|---|---:|---:|
| 交易数 | 1,135 | 1,135 |
| 总收益（引擎默认，5bps 无滑点） | **+84.21%** | +150.6% |
| 总收益（**实测 COVID 34.9bps**） | — | **+64.8%** |
| CAGR（COVID） | — | 15.6% |
| Sharpe（COVID） | — | 0.55 |
| **最大回撤** | 22.71% ⚠偏乐观 | **45.3%** |
| PF / 胜率 | 1.23 / 51.7% | 1.12 / 50.0% |
| 熔断触发次数 | **1 次**（2023-10-31，dd 21.41%） | |
| 被挡掉的入场 | **5 笔**（1,140 → 1,135） | |

分年（实测 COVID 成本）：2023 **−38.2%** ｜ 2024 **+60.0%** ｜ 2025 **+71.6%** ｜ 2026 **−9.7%**
（同期等权买入持有：中位数 **−80.9%**，只有 16% 的币为正）

### ⚠ 熔断的效果是**一个数据点**做出来的

它只触发了 **1 次**，只挡掉 **5 笔**入场，却把引擎报告的回撤从 43.90% 降到 22.71%，
总收益从 +78.61% 升到 +84.21%。

**一个只生效一次的控制，扛起了整个改善——而那个 20% 的阈值是我在这同一段数据上看着回撤挑的。**
**这是过拟合的表现，不是优点。** 真实净值路径下它的效果小得多
（COVID 回撤 47.0% → 45.3%，收益 +57.9% → +64.8%）。
**请按后者理解，不要按前者。**

### ⚠ 而且第一版熔断是**完全无效的**

第一次交付的版本熔断一次都没触发，却打印出 +78.61% 的漂亮曲线。
根因见第 6 节。**一个静默失效的风控比没有风控更危险。**

## 6. ⚠ 第一版熔断是完全无效的（本轮抓到的最危险的一个 bug）

**交付出去的第一版熔断一次都没触发过**，而回测打印出 +78.61% 的正常曲线。
如果没人去数交易笔数，这个 bug 会跟着策略进生产。

**根因是一行状态重置：**

```python
def bot_loop_start(self, *args, **kwargs):
    self._peak_equity = None      # ← 这个
```

`bot_loop_start` 在回测里**不止被调用一次**（准备数据时按 pair 反复到达），
于是**每次调用都把峰值重置成当前净值**。

调试日志把整个过程记录得很清楚（2023 年那一段）：

```
call #75   equity=111250.41  peak=111250.41  dd=0.0000   ← 峰值创新高
call #100  equity=102072.61  peak=102072.61  dd=0.0000   ← 峰值从 111k 掉到 102k
call #200  equity= 82847.31  peak= 82847.31  dd=0.0000
```

**峰值跟着净值一起下降，所以回撤恒等于 0，熔断永远不触发。**
净值从 11 万跌到 8 万，而「回撤」一路显示 0.0000。

**还有第二层掩盖：**

```python
eq = self.wallets.get_total(...)
if eq is None or eq <= 0:
    eq = float(self.config.get("dry_run_wallet", 1.0))   # ← 这个
```

钱包读不到时回退到初始金额，**把「读不到」变成「看起来净值没变过」**。

**第三层掩盖：** 回测把 `confirm_trade_entry` 包在
`strategy_safe_wrapper(..., default_retval=True)` 里
（`backtesting.py:1191`）——**里面抛的任何异常都被吞掉并放行入场**。
一个失效的风控不仅无效，而且**连报错都不会有**。

**三处都已修：** 状态改成惰性初始化（`_init_state` 一次后不再进入）；
钱包读数失败时**抛错而不是回退**；熔断每次触发都打 WARNING 日志，
并且日志里直接写明「检查 `breaker_trips` 非零」。

> **这是本仓库同一个家族在同一天里的第 5 次。**
> 前四次：3 个月前的 ATR 静默回退、24 币子集常数当全样本界、
> `n` 列碰撞静默换掉表格横轴、`m/σ` 单位错误打印出 t=340。
> **五次全都产出了一张「看起来完全正常」的表。**
> **唯一抓住它们的方式是断言，不是阅读。**
