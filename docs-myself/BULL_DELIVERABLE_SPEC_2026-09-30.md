## 2. ⚠ 修正了什么——四个缺陷，全部在「读者会直接运行」的文件里

这一节是本文最重要的部分。**多头账本在 2026-09-30 发布时带着一个已发布结论、一份配置、零道闸门。**
补闸门的过程找出四个缺陷，其中三个的产物都长得完全正常。

### 2.1 地板用了类默认值 1.5，而不是配置的 4.0（最严重）

```python
# PerpShort4hStop 把配置读进的是 stop_mult，不是 atr_stop
@property
def stop_mult(self): return float(self.config.get("atr_stop", self.atr_stop))

# PerpLong4h.py:179（修正前）——空头分支走 super() 拿到 4.0，多头分支拿到 1.5
return trade.open_rate * lev - self.atr_stop * atr
```

**多头账本被按 4.0×ATR 分配仓位、却按 1.5×ATR 止损。**
证据：835 笔地板绑定的止损里 **797 笔精确落在 1.5，0 笔落在 4.0**；
仓位重算在 4.0 假设下中位误差 6.6%，在 1.5 假设下 159%。
**实际风险 = 1.5/4.0 = 设计值的 37.5%**（约 0.19%/笔，而非 0.5%/笔）。
修正：`self.atr_stop` → `self.stop_mult`。

### 2.2 交付配置缺 `initial_state`

`DELIVERABLE_SPEC_2026-09-30.md` §3 把它列为四个「缺失即静默」的键之一：
缺它，进程每 60 秒心跳、状态永远停在 **STOPPED**、**不产出任何数字且不报错**。
多头配置里它本来就没有。已补。

### 2.3 `exportfilename` 对回测是死键

这个 freqtrade 版本把它标为 deprecated，日志原文：*"has no impact when backtesting"*。
导出目录由 `--backtest-directory` 决定，默认 `user_data/backtest_results`。
**所以 `DELIVERABLE_SPEC_2026-09-30.md` §4 给的那条回测命令——它根本没有 `--export`——
照着跑不会产生任何归档**，也就没有 `cost_reprice.py` 的输入。
而且 `--backtest-directory` 指向一个**不存在**的目录时**不报错**，
而是把整条路径当文件名，在 `user_data/` 根下生成 `user_data/bull_delivered_out-2026-09-29_22-30-50.zip`
——一个长得像目录的文件。

### 2.4 止损可以整个装不上

`custom_stoploss` 的 `return None` 意为「保持原止损」，**只有在原止损已存在时才正确**。
入场 bar 内跌幅已超过地板时，没有任何一根 bar 能装上止损，交易一路滑到 −30% 类兜底。
空头侧同一结构在 1,111 笔里触发 **0** 次；多头修地板前 993 笔里 **1** 次（UNI，−30.00%，
次差的一档是 −8.14%——止损距离分布里不会有这种洞）。

**⚠ 已实测：为此加的「越界即按市价离场」夹紧，在回测里效果为零。**
数字前后完全一致。它被保留为正确性防护，但**不宣称它修好了任何东西**。

## 3. 策略逻辑

```
入场（三条件合取，全部因果，Donchian 与波动中位数 shift(1)）：
    rvol   = volume / volume_sma(20)          >= 2.0     放量
    close  > high.rolling(20).max().shift(1)              20 根 bar 向上突破
    vol42  < vol42.rolling(365).median().shift(1)         低波动过滤

出场（exit_mode="run"，无止盈、无时间止损）：
    地板   = 入场价 − 4 × ATR(14, 入场 bar)              永不放宽
    吊灯   = (入场以来最高价) − 8 × ATR(当前 bar)
    止损   = max(吊灯, 地板)
    熔断   = 回撤 ≥ 20% 时停止入场 42 根 bar
```

## 7. ⚠ 那个 bug 其实是「账面更好看」的——以及为什么不据此交付 1.5

**等风险对照（都按各自真实风险 0.1875%/笔跑）：**

| 账本 | 交易 | 收益 | PF | 回撤 | 胜率 |
|---|---:|---:|---:|---:|---:|
| 1.5×ATR 地板（那个 bug） | 1,000 | **+95.43%** | 1.37 | 27.61% | 16.0% |
| 4.0×ATR 地板（配置值） | 921 | +42.09% | 1.31 | **23.70%** | 26.1% |

**等风险下，那个 bug 的账面好一倍多。所以它不是一个中性的笔误。**

**仍然交付 4.0，理由三条：**
1. 选 1.5 是**看完结果之后**挑的，正是本项目整套装置要防的那件事；
2. 空头账本在同一面板上专门测过止损倍数前沿并**明确选了 4.0**
   （`PREREG_STOP_MULTIPLE_2026-09-28.md`），多头用 1.5 会让两本账的风险架构不一致；
3. 1.5 作为一个**假设**上报，附上完整数字和上面的对照。若要采用，
   应在配置里**显式写 `atr_stop: 1.5`** 并重新走一遍闸门——让它成为一个声明的选择，而不是一个事故。

## 9. 边界（必须一起读，否则会误用）

1. **不是选币 alpha。** 与空头同源，是择时工具。
2. **不统计显著。** 空头账本 t ≈ 0.58 且已证明在本样本不可证伪；多头没有单独做过显著性检验，
   **不应假定它更好**。
3. **吊灯 8.0 是在样本里仅有的两个上涨年份上选的，而且这两年互相矛盾**
   （2023 要 8.0，2024 要 12.0）。2025 是 −18.4%。
4. **部分币的 4×ATR 地板比 −30% 类兜底还宽**（FARTCOIN 31.2%），此时兜底生效、
   实际止损比设计更紧。已测量 1 笔，报为警告而非失败。
5. **前瞻确认需要 6.8 年，且最终保留集已于 2026-09-26 烧毁。**
   采集器已在跑（PID 随重启变化，`dry_run: true`，凭证为空），0 笔成交属正常。
6. **回撤 49.6% 不是能舒服持有的东西。** 它换来的是 +26.2%，CAGR 7.0%。
7. **不要再改配置。** 采集器只读一次配置，改了会污染序列。
