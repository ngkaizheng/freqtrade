# 结果 E-1：事件率不是杠杆——三个过滤器在**同一批 bar** 上触发，4h 这条线正式关闭

日期：2026-09-30 · 预注册：`PREREG_EVENT_RATE_2026-09-30.md`
· 工具：`tools/perp_short/event_rate.py` · 原始输出：`user_data/logs/event_rate.txt`
· 网格：`user_data/perp_short_out/event_rate.csv`

**判定：E2 失败（最好的放松只有 1.88×，门槛 2.0×；而 t=2 需要 11.9×）。**
**4h 永续空头这条线到此正式关闭，关闭的理由从「成本」换成了「n_eff」，而且现在有了机制。**

## 0. 为什么这是最后一个值得试的杠杆

`RESEARCH_STATE.md` §15c 测出来：

| | |
|---|---:|
| 每笔净 R | +0.1173 |
| 成本占毛值 | **11%** |
| 达到 t=2 需要的独立时间戳 | **1,159** |
| 实际拥有的 | **423** |
| 平均同时持仓 | **3.0** |

**瓶颈不是每笔赚多少，是样本里没有那么多次独立交易。**
本项目此前所有工作（止损倍数、流动性阶梯、方向开关）都在优化**每笔 edge**，
**从来没有人把「事件率」当成目标**。这是一次有新理由的重开，不是事后找的。

## 1. E1 先验证计数口径

| | |
|---|---:|
| 冻结信号在 40 币、3.67 年里触发 | **2,169 次** |
| 每币每年 | 14.8 次 |
| 引擎实际成交 | 1,111 笔 |
| **比值** | **1.95×** |

**1.95× 是合理的上界关系**：信号是无上限的，但引擎有 `max_open_trades=24` 的并发上限，
且同一币持仓期间不能重复入场，两者都会丢弃信号。**所以计数应该 ≥ 成交数，而不是相等。它确实是。**

## 3. 真正的发现：三个条件**高度正相关**

| 条件 | 单独通过率 | 单独会产生的信号数 |
|---|---:|---:|
| rvol ≥ 2.0 | 7.06% | 6,809 |
| close < 20-bar Donchian 低点 | 4.14% | 3,990 |
| 低波动（vol42 < 自身 365 中位） | 55.13% | 53,153 |
| **三者合取** | **0.89%** | **853** |

**如果三个条件独立，合取应该通过 7.06% × 4.14% × 55.13% = 0.16%。**
**实测是 0.89%——比独立假设高 5.6 倍。**

**也就是说：放量、20 根 bar 内的向下破位、以及「相对自身历史算低波动」，
在很大程度上是同一批 bar。** 高成交量 bar 往往就是大幅下跌 bar，
而大幅下跌 bar 相对该币自己的历史也常常算「低波动」。

**所以放松任何一个条件都买不到新事件——因为另外两个条件已经把同一批 bar 选掉了。**
**这就是为什么整张网格都挤在 1.0×–1.9× 之间。**

**这不是「过滤器太严」，是「这三个条件描述的是同一件事」。**
把它们调松不会让市场多给你信号，只会让信号变差。

## 4. 判定

| 门槛 | 判据 | 结果 |
|---|---|---|
| E1 | 计数与引擎对得上（≥） | **PASS**（1.95×） |
| **E2** | 至少一个放松 ≥ 2.0× | **FAIL**（最好 1.88×） |
| E3 | 达到 t=2 所需的 11.9× | **FAIL** |
| E4 | 本轮不回测 | 遵守 |

**按预注册的失败条件：4h 这条线正式关闭，理由是 n_eff，不是成本。**

**这和前几轮的关闭理由不同，而且更硬：**
* 成本只占毛值 11%——不是瓶颈（§15b）；
* 横截面几乎是单一因子——加标的没用（§15c-3）；
* 缩短周期让 cost_R 差 2.10 倍、毛 edge 更小（§18a/§18c）；
* **现在连「多来几次信号」这条路也堵死了：最好 1.88×，需要 11.9×。**

**四条独立的门全部关上，而且每一条都是量出来的，不是论证出来的。**

## 5. 有意留下的东西

**「放量 + 破位 + 低波是同一批 bar」这个相关性本身是可用的知识**，
只是它指向的是**收紧**而不是放松：
**如果三个条件高度重合，那么用三个条件筛等于只用一个条件筛——
第三个过滤器没有增加任何信息。**
本项目此前一直把低波过滤器当作一个贡献条件
（`WIDE_PANEL_RESULT` 记录它「在 51% 的交易上贡献 +38–43% 毛收益」），
**这个测量与「它不增加信息」并不矛盾**：一个条件可以提高信号质量而不提高信号数量。
**但它确实意味着，这个信号本质上是一个信号，不是三个。**

**6.8 年的前瞻检验仍然开着**，那是收集数据，不是研究。

## 6. 这一轮自己的 bug（值得记，因为它们有一个共同形状）

写这个脚本时我踩了三个坑，**每一个都产出了一张看起来正常的表**：

1. **`pd.to_datetime(RangeIndex, utc=True)` 把整数当成纳秒**——
   我为了修一个 NaN 错误加了 `.reset_index(drop=True)`，日期索引被丢掉，
   于是 8034 根 bar 变成 1970-01-01 起 8 微秒，**所有时长都算成 0.00**，
   而信号计数 2,169 **一直是对的**。**时钟坏了，尺子没坏，而输出看起来完全正常。**
2. **算出来但没用的变量**：`implied = rate_base * years * n_symbols`
   把「已经跨币加总的总数」又除又乘，报出 40 笔「隐含交易」而实际是 2,169。
3. **一段死代码**在算一个值然后丢掉，还在上面抛 TypeError——
   **表格里有一行看起来存在、其实不存在的格子，比少一行更糟。**

**共同形状：这三处都在「时间/计数」这条通路上，而这条通路上没有断言。**
E1 之所以能抓住它们，正是因为它**要求这个数字和引擎的已知数字对得上**——
**一个能对账的门槛，比十个看起来对的表格有用。**
